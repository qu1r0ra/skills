# Skills default to this collection; standalone repos require a technical forcing function

`adversarial-review-agy` was split into its own repo because it dispatches to an external paid CLI and needed a genuinely different install/trust/security story. That raised the question of whether `adversarial-review` — its sibling in this collection — should follow, purely for symmetry. Decided: no. Skills stay in `qu1r0ra/skills` by default; a skill graduates to a standalone repo only when it needs something the collection genuinely can't give it (a distinct install/trust/security story, external dependencies, its own CI), not for visibility or because a sibling happened to split. Wanting a skill publicly visible is handled by making this collection's repo public, not by fragmenting it.
