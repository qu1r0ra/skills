# Teaching principles and upstream ownership

Read [teach's Philosophy, The Mission, Knowledge, and Skills sections](../../teach/SKILL.md) as reference when designing the outcome path. `teach` is user-invoked: reading its principles does not invoke its workflow. If it is missing, report the dependency before planning.

Apply those principles to a resource as follows:

| Upstream principle | Resource-authoring adaptation |
| --- | --- |
| Mission grounds each lesson. | The owner-confirmed brief grounds each resource and decides which project knowledge matters. |
| Knowledge comes from trusted resources. | Inspect authoritative project material and use primary sources for gaps; keep claims traceable. |
| Challenge fits the learner's starting point. | Design from the agreed audience profile, separating subject expertise from project familiarity. Reassess assumptions when the audience changes. |
| Practice and feedback develop skills. | Select a task, explanation prompt, critique, or other check that fits the intended outcome. Include explanatory feedback when practice is chosen. |
| Fluency can overstate durable learning. | Distinguish a clear resource and immediate self-check from demonstrated retention or transfer; describe evaluation limits honestly. |

The new workflow owns mission/audience confirmation and reusable resource production. Upstream `teach` owns live lessons, learner-specific progression, learning records, and multi-session state. Its HTML lesson layout, interactive lesson defaults, workspace files, and component conventions belong to that workflow. This resource uses the confirmed medium and project conventions. Consult [authoring-guide.md](authoring-guide.md) for independently researched support and scope limits on the adaptations above.
